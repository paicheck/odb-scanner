# ODB Scanner — Android app

The Android companion to the Python `odb_scanner` collector. It speaks the same
read-only UDS protocol to the same ELM327 adapter over classic Bluetooth SPP,
and decodes the same DID map — because both are driven by one shared spec.

```
spec/odb_scanner.json  <-  generated by tools/export_spec.py (single source of truth)
        |
        +--> Python collector (Windows)     reads it at build time via the live registry
        +--> Android app (this directory)   bundles it in assets/spec.json
```

## What it does

* **Bluetooth SPP transport** — `transport/BluetoothSpp.kt` (RFCOMM socket) +
  `transport/Elm327Protocol.kt` (ELM327 AT commands + the per-ECU addressing
  quirks the v1.5 clone needs: `ATCAF1`+bare+flow-control for 11-bit modules,
  `ATCAF0`+`ATCRA`+`ATFCSM 0` for 29-bit modules).
* **Read-only guard** — `uds/ReadOnlyGuard.kt` enforces the exact allow-list
  from the spec (`uds.py`'s `validate_request`, verbatim: service, sub-function,
  length limits). Nothing reaches the bus without passing through it.
* **DID read + decode** — `uds/Uds.kt` (ISO-TP reassembly + NRC) and
  `spec/Decode.kt` (scalar arithmetic + the named special decoders).
* **Collection loop** — `collect/Collector.kt` (discovery, polling, and the
  NRC-0x31 / silent-DID retirement that stops re-polling dead DIDs).
* **UI** — `MainActivity.kt` (Jetpack Compose): connect, discover, collect, and
  list decoded values.

## Build

Open `android/` in Android Studio (or run `./gradlew assembleDebug` after
generating a wrapper). It targets:

* `compileSdk 34`, `minSdk 26` (Android 8.0+)
* Kotlin 2.0, Jetpack Compose, Kotlin coroutines

`spec.json` is bundled in `app/src/main/assets/`. Regenerate it after any DID
or decode change in the Python repo:

```powershell
python tools/export_spec.py
Copy-Item spec\odb_scanner.json android\app\src\main\assets\spec.json
```

## Safety (non-negotiable)

This app is **strictly read-only**. The only requests it can send are the
allow-listed ones in `spec.json` (`0x10 0x01`, `0x22`, `0x19` read sub-functions,
`0x3E`, OBD-II `0x01/0x03/0x09`). `uds/ReadOnlyGuard.kt` is the choke point and
must never be weakened; a port must not add a "send arbitrary bytes" API.
